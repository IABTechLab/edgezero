# Spin KV geography production design

Status: approved. Supersedes the Spin geographic-assertion portion of the previous Cloudflare/Spin design; Cloudflare and Axum acceptance remains.

## Goal and existing foundation

Complete issues 480 and 486 using Cloudflare native metadata and Spin geography resolved from an explicitly pinned immutable KV dataset. Deployment topology is not assumed.

Live PR454 commit 925fe01926e2ad71222d274610b7c80b0918de48 contains portable async core geo::kv, native managed serving, dataset builder, integrity validation, immutable publisher and verification. It already contains exact PR502 commit 8cd7af96e94778df359e7ffed05be595fbfd901f. PR514 b04f9ccd2d8579afeb8a4c85ba93cb436e7140a7 adds the existing authenticated geographic assertion path. Integrate 454 by an ordinary merge into 514, preserving published history, and retarget 514 to feature/kv-geoip. No parent edits, rebases or force pushes. Union overlapping core provenance changes, then remove the superseded SpinIngress API from the final delta.

## Source and trust

Choose KV plus authenticated visitor-IP admission. This reuses the portable dataset and current credential mechanism, without requiring an ingress service to determine geography. It still requires an operator-controlled proxy to replace the original visitor-IP header and credential. Deployment topology is not established by this implementation. Never trust arbitrary Forwarded, X-Forwarded-For, spin-client-addr, or a client-supplied country/region.

Use fixed x-edgezero-geo-ip and x-edgezero-geo-token. Token admission retains existing 32–128-byte visible ASCII syntax, exact single-value handling, constant-time comparison, bounded Spin variable lookup, original-header admission budgets, and removal before public request snapshots or callbacks. Capture both token and visitor-IP assertion into bounded private values and remove both headers after accounting the original head and before creating the admission snapshot. An authenticated IP must be exactly one strict IpAddr with no ports, whitespace, lists or zone identifiers; canonicalize IPv4-mapped IPv6. Missing/duplicate/invalid credential fails closed before any KV read. After successful authentication, missing IP is MissingReaderIp, duplicate/malformed IP is UntrustedIngress. Do not echo IP or token in logs, errors or debug output. Credential variable name is non-secret configuration; secret value remains in Spin variable providers.

Resolve into existing private immutable GeoOutcome with provider identity kv, source Kv, and AuthenticatedIngressHeader trust basis (meaning this credential-gated IP assertion, not host socket attestation). Keep existing NoMatch, UnsupportedGeography and ProviderFailure semantics. Corrupt/missing pinned data is an error, never a different generation or fallback to headers. Applications explicitly decide policy on unavailable/error; a selected geo error does not itself change ordinary HTTP status.

## Configuration and lifecycle

Extend existing ManifestAdapterGeo and EnvConfig conventions for [adapters.spin.geo], with provider off (default) or kv. KV requires store_id, pin, reader_ip = "authenticated-header", and credential_variable. lookup_timeout_ms defaults to 250 and must be 1..=30000. The same EDGEZERO__ADAPTER__GEO__* overrides take precedence on Spin. provider=off rejects source settings. Reject CloudFront-only fields, max_in_flight (no misleading per-process limit), unknown manifest keys and unknown EDGEZERO__ADAPTER__GEO__* override keys, unsupported provider/input combinations, invalid variable names, undeclared logical store ids, and malformed pins. Axum rejects Spin-only settings; Cloudflare/Fastly continue rejecting geo selection tables. Both run_app and dispatch_app apply the same configuration rules. Add a narrow EnvConfig prefix-key enumeration helper to validate this namespace without exposing values in diagnostics; do not change unrelated namespace behavior. Validate merged static selection before invoking request lifecycle callbacks; use existing typed assembly-error behavior. Configuration errors are not ordinary missing geography.

Selection state contains immutable configuration only. After request admission and credential verification, obtain the existing declared KV registry handle and create Resolver for this request. Open pinned manifest, verify both roots, and lookup using current core reader. Bound all secret/preparation/lookup work by remaining admitted request deadline; bound KV preparation plus lookup additionally by one absolute deadline created once immediately after authentication, capped by lookup_timeout_ms and the remaining admitted deadline. Do not reset this deadline between manifest, roots and lookup. A secret failure yields ProviderFailure without reading KV. Timeouts cancel guest futures; no claim of cancelling host work. No retained Spin Store resource, future, global resolver or cross-request cache. Bound request-local validated cache to 1 MiB/16 entries, max object 384 KiB and max path 3 objects, consistent with the qualified artifact shape. SDK materializes values before core validates size; these are guest validation/cache limits, not a hard host allocation ceiling. Document repeated manifest/root reads and cold request cost; platform capacity controls govern aggregate concurrency.

## Dataset publication

Serving performs exact-key reads only. Provide a separate operator-only Spin loader using ordinary SpinKvStore binary writes and the existing validated publisher. No serving bootstrap writes, public serving upload route, native database-format writes, active-generation key, or hosted deployment automation.

Expose only existing offline artifact/publication modules as a small library in examples/geo-kv-prototype (optional publisher feature; native SDKs remain optional). Keep CSV import/main separate. A standalone excluded examples/geo-spin-loader component mounts an existing artifact directory read-only at /artifact. Its single authenticated POST validates Artifact::open before opening the target Spin store; then invokes existing publish (identical replay, conflict rejection, readback, manifest last) and full remote verify. Return aggregate counts and pin, no addresses, secrets or raw backend errors. Pin selection remains an explicit serving configuration change after verification.

An operator runner starts the loader only on loopback using an ephemeral variable credential, invokes it, and stops it on success/failure, timeout or interruption. Give runner readiness and total publication finite configurable deadlines (defaults 30 seconds readiness, 10 minutes publication); fail closed if either expires, with a cleanup-on-timeout test. Supply the ephemeral credential through a Spin environment-backed variable provider and send the POST from process memory, never secret-bearing process arguments or files. Stage the artifact inside the temporary application directory required by Spin and remove the owned copy on exit. It must never expose the endpoint on the serving app. Loader and serving use the same explicit named store and absolute backend path/runtime configuration; a relative .spin path is insufficient proof of shared storage. Default local SQLite backing is a supported rehearsal; external Spin backends remain subject to their documented configuration and hosted qualification. Exclusive single publisher per generation remains required; read-before-write is not a distributed lock. No licensed artifact or source data enters Git or release images. Loader must compile for the actual selected WASI/Spin SDK versions before acceptance.

## Acceptance and limitations

Real Spin4.1 runtime proof must build a synthetic IPv4/IPv6 artifact through 454 tooling, publish through the operator loader, stop it, start a separate serving component on the same store, and observe US/CA through ctx.geo(). Also country-only, gaps, unsupported geography, invalid/missing/corrupt objects, wrong pins, missing store permissions, input spoofing/duplicates, secret failures, deadlines, repeated requests and retained dispatch_app; prove sensitive headers are absent from every public callback. Include deliberate broken controls that discriminate missing lookup and credential enforcement. Prove publication idempotence/conflicts/tampering and no serving writes.

Preserve Cloudflare native metadata and forged-header resistance, Fastly behavior, Axum manifest-only activation and normal Spin bodies/routes. Complete required project checks, WASM contract suites, actual application runtimes, fresh independent review and all actionable findings before publishing signed commits and updating draft514. Production load/capacity, geography accuracy, data licensing, host-side cancellation, and external-backend permissions are not certified by local tests.
